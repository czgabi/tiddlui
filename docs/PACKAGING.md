# Packaging & releasing (Linux)

This documents how Tiddlui is packaged for Linux. All artifacts derive from a single
`npm run tauri build`.

## Artifacts

| Target        | Produced by                              | Distribution            |
| ------------- | ---------------------------------------- | ----------------------- |
| `.deb`        | Tauri bundler (`bundle.targets: "all"`) | Debian/Ubuntu, Releases |
| `.AppImage`   | Tauri bundler                            | Distro-agnostic, Releases |
| `.rpm`        | Tauri bundler                            | Fedora/openSUSE, Releases |
| AUR `tiddlui` | `packaging/aur/PKGBUILD`                 | Arch User Repository    |

The Tauri bundle output lands in `src-tauri/target/release/bundle/{deb,appimage,rpm}/`.

## GitHub release flow (CI)

[`.github/workflows/release-linux.yml`](../.github/workflows/release-linux.yml) builds the Linux
artifacts on `ubuntu-latest` and attaches them to a GitHub Release. It runs when a `v*` tag is
pushed (and can be triggered manually via *workflow_dispatch*):

1. Tag a release: `git tag v1.4.0 && git push origin v1.4.0`.
2. CI installs the WebKitGTK/GStreamer/ffmpeg deps, builds the sidecar and the app, and uploads
   the `.deb` + `.AppImage` to the release.

## AUR package

The AUR package `tiddlui` (in [`packaging/aur/`](../packaging/aur/)) builds from an upstream
release tarball, so **publish a GitHub Release first**, then:

```bash
# 1. Update the version and checksums
cd packaging/aur
# edit pkgver in PKGBUILD to match the new tag, then:
updpkgsums                       # fills in sha256sums from the release tarball
makepkg --printsrcinfo > .SRCINFO

# 2. Test the build locally
makepkg -si

# 3. Push to the AUR (requires an AUR account + SSH key)
git clone ssh://aur@aur.archlinux.org/tiddlui.git aur-tiddlui
cp PKGBUILD .SRCINFO aur-tiddlui/
cd aur-tiddlui
git add PKGBUILD .SRCINFO
git commit -m "tiddlui 1.4.0"
git push
```

> `.SRCINFO` is generated by `makepkg --printsrcinfo` and must be committed alongside any
> `PKGBUILD` change — the AUR rejects pushes without a matching `.SRCINFO`.

### Notes

- `build()` fetches npm/cargo dependencies from the network. This is standard for Tauri/Electron
  AUR packages but means the package can't be built in a fully network-isolated chroot.
- The installed binary is the Rust target `tiddl-gui`, installed as `/usr/bin/tiddlui`.
- The `.desktop` entry launches with `WEBKIT_DISABLE_COMPOSITING_MODE=1` (see
  [`LINUX.md`](LINUX.md#wayland)).
